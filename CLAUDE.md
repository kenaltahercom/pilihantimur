# Pilihan Timur (dulu "Enam Pilihan NTT", awalnya "Ragam Timur") — catatan proyek

Panduan wisata bilingual (ID/EN) untuk seluruh NTT. Sumber kebenaran produk: `docs/product/PRD.md` (v1.0 draft).
Bahasa komunikasi dengan pemilik: Indonesia.

## Status
Prototype statis (HTML/CSS/JS murni) untuk validasi tampilan + gerak. BUKAN stack final PRD §15
(Next.js, Tailwind, Supabase, next-intl). Porting ke Next.js dijadwalkan setelah tampilan disetujui.

## Perintah
- Build: `node src/build.mjs` (tanpa dependensi; hasil di `dist/`)
- Lihat lokal: `python3 -m http.server 8077 --directory dist` → http://localhost:8077/id/index.html

## Struktur
- `src/data.mjs` kandidat destinasi (32 per 9 Nov 2026; awalnya 45 dari PRD §8) · `src/i18n.mjs` teks ID/EN · `src/scenes.mjs` ilustrasi placeholder · `src/build.mjs` template
- `assets/css/app.css` token + komponen + gerak · `assets/js/app.js` interaksi · `docs/decisions/` ADR

## Aturan penting
- Semua destinasi = KANDIDAT belum diverifikasi. Jangan mengisi deskripsi, koordinat, akses, atau foto tanpa sumber (PRD §8 "Persyaratan sebelum publish").
- Foto wajib punya lisensi/izin jelas. Ilustrasi di prototype hanyalah placeholder.
- Jangan menyalin logo/ilustrasi/foto/copy Coparadiso. Hanya pola interaksi & karakter tipografi (ADR 0001).
- Gerak harus menghormati `prefers-reduced-motion`; konten tidak boleh bergantung pada JS.
- Kontras WCAG AA: gunakan `--sea-deep`/`--terra-deep` untuk teks krem di atas latar berwarna.

## Port Next.js (`web/`)
Status: semua 9 tipe halaman × ID/EN sudah diport (111 halaman statis). Prototype statis tetap jadi acuan visual.
- Perintah (di `web/`): `npm run dev|build|start|lint|typecheck|test`. Di sandbox ini npm perlu `env -u npm_config_noproxy -u NO_PROXY -u no_proxy npm ...`.
- Skema Supabase ada di `web/supabase/` (5 migrasi + seed + tes RLS). Sudah diterapkan ke proyek Supabase `ragam-timur` (ref dbloglhvyiztokputikj); lihat README di sana.
- Supabase dipakai oleh `/admin` dan (hanya data terbit) halaman publik (login email+kata sandi, daftar destinasi). `src/proxy.ts` menjaga `/admin` lewat sesi Supabase; server tetap memeriksa peran dari tabel `profiles`.
- Env: salin `web/.env.example` ke `web/.env.local`. Jangan pernah memakai kunci service_role di klien.
- Admin punya editor destinasi (`src/app/admin/destinations/[slug]/`): terjemahan ID/EN, koordinat, sumber manual (label domain + saran P1/P2/P3 dari `src/lib/sources/trust.ts`), verifikasi, ajukan pemeriksaan. Sumber diisi MANUAL; tidak ada pencarian/draf otomatis (dilepas, butuh kunci API berbayar). Fakta wajib berasal dari sumber (aturan PRD §8).
- Penerbitan: admin menekan Terbitkan (butuh terverifikasi + ≥1 sumber + ringkasan ID & EN, dijaga trigger DB). Halaman publik menggabungkan 32 kandidat (`data.ts`) dengan destinasi terbit dari Supabase (`src/lib/published.ts`, ISR 5 menit + revalidasi saat terbit); gagal-aman ke kandidat.
- PERINGATAN uji: database Supabase berisi data sungguhan pemilik (mis. `pantai-pede`). Uji tulis harus pada destinasi kosong dan dalam transaksi yang di-ROLLBACK; jangan menimpa/memulihkan data.
- Foto berlisensi: admin unggah JPG/PNG/WebP (maks 5 MB, 12/destinasi) ke bucket publik `media`; foto terbit hanya bila ada teks alt ID+EN, kredit, dan lisensi/izin (dijaga constraint DB `media_publish_alt`); hanya admin yang menerbitkan/memilih foto utama. Halaman detail menampilkan foto terbit + kredit; tanpa foto → ilustrasi placeholder. Bucket publik memakai nama berkas uuid (draf tidak ditautkan tapi URL-nya publik bila diketahui).
- Laporan koreksi: pengunjung mengirim dari halaman destinasi (`ReportForm` + server action memakai kunci publik; kolom jebakan anti-bot). DB membatasi: pelapor hanya bisa INSERT (status selalu 'open'), batas 10/jam/destinasi dan 60/jam total, tak bisa membaca. Staf menangani di `/admin/reports` (hanya status + catatan yang bisa diubah). Kontak pelapor privat.
- Foto terpasang (tahap awal, tanpa unggah ke bucket): berkas di `web/public/photos/<slug>/NN.jpg` + data (alt ID/EN, kredit, ukuran) di `web/src/lib/photos.ts`; foto DB yang terbit selalu didahulukan. Pengelola menyatakan semua foto kirimannya berlisensi (jangan ditanya ulang); kredit hanya yang terlihat pada foto/berkas, selain itu "Koleksi Ragam Timur". Alur batch: ekstrak zip → cocokkan nama folder dengan nama destinasi → lihat tiap foto → `scripts/enhance_photos.py` (standar tetap untuk SEMUA foto: potong 4:3 dengan titik fokus, perbesar x2 dengan FSRCNN bila lebar <1600, maks 1600x1200, tajamkan ringan, buang EXIF; model `FSRCNN_x2.pb` diunduh dari github.com/Saafke/FSRCNN_Tensorflow; EDSR terlalu lambat di CPU) → tulis alt ID+EN dari apa yang TERLIHAT → tes `tests/photos.test.ts`. Foto yang tampak milik lokasi lain / bukan foto netral (mis. rombongan pejabat berlogo) ditahan di `photos-tertahan/<slug>/` dan dilaporkan, bukan dipasang. Watermark/logo pihak ketiga TIDAK dihapus (hapus watermark = menghilangkan atribusi); minta berkas asli tanpa watermark atau biarkan dengan kredit sumbernya. Pengelola tidak mau zip dikirim tiap batch; cukup kabari bila selesai.
